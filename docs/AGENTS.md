# Инструкции для `docs/`
- Поддерживайте записи об архитектуре в соответствии с последней версией среды выполнения, описанной в `docs/architecture_assessment.md`. Обновляйте диаграммы, таблицы и выноски при изменении коннекторов, конвейеров или контрактов на хранение.
- При добавлении новых планов или отчетов явно указывайте, на какой микросервис/домен они влияют (прием данных, ценообразование, хранение, пользовательский интерфейс), чтобы будущие рефакторинги можно было быстро оценить.
- Предпочитайте краткие, ориентированные на действия разделы: **Контекст → Результаты → Решения → Следующие шаги**. Длинные повествования следует переносить в приложения.
- Каждый документ по архитектуре или плану должен содержать ссылки на соответствующие пакеты Go (например, `cmd/screener-core`, `internal/launcher`, `internal/dex/pricing`) для обеспечения прослеживаемости.
