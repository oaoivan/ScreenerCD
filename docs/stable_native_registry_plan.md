# План унификации справочников стейблкоинов и нативных токенов

## Анализ текущего состояния
- Списки стейблкоинов и адреса нативных активов дублируются в нескольких коннекторах (`internal/dex/Etherium/Uniswap/v2_connector.go`, `internal/dex/Etherium/Uniswap/connect_uniswap_v3_all.go`, тестовых скриптах).
- Графовый прайсер (`internal/dex/pricing/graph_pricer.go`) получает список якорей вручную, из-за чего расширение сетей требует правок кода.
- Конфигурация YAML не содержит единого раздела для справочников активов; добавление новой биржи приводит к расхождению списков.

## Предлагаемое решение
Ввести единый реестр активов (стейблы/нативные токены) на уровне конфигурации и пакет-лоадер, который поставляет данные всем коннекторам и прайсеру через общий интерфейс.

## Пошаговый план
1. **Инвентаризация данных**
   - 1.1 Собрать перечень используемых стейблов и нативных токенов по всем сетям из текущего кода.
   - 1.2 Зафиксировать обязательные атрибуты (символ, адрес, decimals, chain ID, тип).

2. **Дизайн схемы конфигурации**
   - 2.1 Создать `configs/assets/tokens.yaml` с разделами по сетям (`ethereum_mainnet`, и т.д.) и типами (`stable`, `native`).
   - 2.2 Описать структуру YAML в `docs/README.md`/`docs/project_documentation.md` (раздел о конфигурации DEX).

3. **Новый пакет для загрузки активов**
   - 3.1 Добавить пакет `internal/assets` с моделями `TokenInfo` и перечислением типа токена.
   - 3.2 Реализовать загрузчик YAML с валидацией адресов, decimals и обязательных полей.
   - 3.3 Добавить кэширование результата и метод фильтрации по сети и типу.

4. **Интеграция с конфигом приложения**
   - 4.1 Расширить `configs/screener-core.yaml` ссылкой на файл справочника.
   - 4.2 Обновить `internal/config/config.go`, чтобы поле `AssetsConfigPath` попадало в `DexConfig`.

5. **Использование в прайсере**
   - 5.1 Заменить ручную инициализацию стейблов в `internal/dex/pricing/graph_pricer.go` на данные из `assets.Provider`.
   - 5.2 Добавить unit-тесты на корректность построения графа при наличии нескольких стейблов.

6. **Рефакторинг коннекторов**
   - 6.1 В `internal/dex/Etherium/Uniswap/v2_connector.go` заменить локальные карты стейблов/нативных адресов вызовами `assets.Provider`.
   - 6.2 Аналогично обновить `internal/dex/Etherium/Uniswap/connect_uniswap_v3_all.go` и другие DEX коннекторы.
   - 6.3 Обновить тестовые/скриптовые коннекторы, чтобы использовать общий провайдер или ссылаться на YAML.

7. **Проверки и документация**
   - 7.1 Добавить интеграционный тест (или mock) проверяющий, что коннектор корректно получает адреса из нового реестра.
   - 7.2 Обновить инструкции по добавлению новой биржи (docs) с описанием шагов расширения `tokens.yaml`.

8. **Каталоги и миграции данных**
   - 8.1 Перенести существующие JSON/константы с адресами в новый YAML и удалить дубли в коде.
    - 8.2 Подготовить скрипт/утилиту для валидации `tokens.yaml` (например, проверка дублей и checksum адресов).
   Реализовано утилитой `go run ./test_scripts/assets/validate_tokens.go`: она валидирует адреса, проверяет decimals и в рабочем режиме автоматически дополняет skip-листы (`stableSkipSet`, `isStablecoinOrFiat`). Подробный порядок запуска описан в `docs/project_documentation.md` (раздел «Asset Registry»).
